# Workflow Rules

## 1. 작업 단위

- 한 번에 하나의 작업만 수행한다.
- 여러 페이지를 동시에 수정하지 않는다.
- 리팩토링, 디자인 수정, 기능 추가를 한 작업에 섞지 않는다.
- 작업 전 수정할 파일 목록을 먼저 제안한다.
- 사용자가 승인하기 전 다음 단계로 넘어가지 않는다.

## 2. 리팩토링 규칙

- 리팩토링의 목적은 구조 개선이다.
- 리팩토링 중 시각적 결과물을 변경하지 않는다.
- 기존 className, HTML 구조, CSS 선택자를 임의로 변경하지 않는다.
- 컴포넌트 분리 시 먼저 큰 섹션 단위로 나눈다.
- 세부 컴포넌트 분리는 실제 반복 구조나 상태 책임이 생긴 뒤 진행한다.

## 3. 디자인 수정 규칙

- 디자인 수정은 별도 작업으로 진행한다.
- 디자인 수정 작업에서는 기능 추가를 하지 않는다.
- 기존 리뉴얼 방향과 다른 새로운 디자인 해석을 임의로 추가하지 않는다.

## 4. 기능 추가 규칙

- 기능 추가 전 요구사항을 먼저 확인한다.
- MVP 제외 범위 기능은 구현하지 않는다.
- 로그인, 회원가입, 장바구니, 결제, 주문 처리, 관리자 기능은 추가하지 않는다.
- 제외된 기능이 필요한 버튼은 실제 기능 대신 MVP 제외 안내 메시지만 표시한다.

## 5. 문서화 규칙

- 향후 다시 참조해야 할 설계 결정은 대화에만 남기지 않고 `docs/` 아래에 문서로 기록한다.
- 예: Header 세부 분리 계획, 상품 데이터 구조 변경 계획, 검색/필터 상태 관리 방식
- 문서는 실제 코드 상태에 맞게 점진적으로 추가한다.

## 6. 검증 규칙

작업 후 `docs/verification.md`를 기준으로 검증한다.

기본 검증 항목:

- `pnpm lint`
- `pnpm build`
- `pnpm dev`
- `/`
- `/products`
- `/products/[id]`
- 모바일 375px 레이아웃
- MVP 제외 범위 위반 여부
